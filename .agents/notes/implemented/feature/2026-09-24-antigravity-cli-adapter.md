# Agent Note: an Antigravity CLI (agy) provider route, driving a full coding agent as a text-only chat backend

Status: implemented

English | [中文](2026-09-24-antigravity-cli-adapter.zh.md)

## Problem

The local Antigravity CLI (`agy`, v1.2.0) gives an already-logged-in path to Gemini, Claude, and GPT-OSS models without a separate API key, but it is not an LLM API: it is a full coding agent with ~60 built-in tools (`run_command`, `view_file`, `write_to_file`, …), a permission system, and its own system prompt agy assembles internally before this adapter's stdin is even read. Driving it as a harness chat backend means keeping it from acting on that agency at all — never running its own tools, never trusting its own read/write permission model — while still answering exactly the text (or, for tool-calling requests, the JSON) the harness agent loop needs, streamed through the same `StreamChunk` protocol every other adapter implements.

Two facts made this harder than an ordinary adapter: agy exposes no `--tools` flag this adapter could drive, and `--json-schema` was measured unreliable (the model ignored it and ran an extra turn against agy's own tools instead of answering). Harness tool calling therefore has to be implemented entirely in the prompt, and agy's own tool use has to be fenced by something stronger than asking nicely.

## Decision

`packages/llm/llm-antigravity` (`@deepseek-ai/dsh-llm-antigravity`) is a new provider package owning the single route `antigravity`, mounted opt-in only — no shipped bundle references it, because `agy` is a locally installed, separately licensed and separately authenticated CLI this harness cannot assume is present.

### agy is an agent, not a completion API

Every prompt this adapter sends opens with a fixed preamble (`COMPLETION_BACKEND_PREAMBLE` in `src/prompt.ts`) telling the model it is serving as a text completion backend for another agent runtime and must never invoke its own built-in tools. The preamble is necessary but not sufficient: a model can ignore instructions. The actual enforcement is structural — every `stream()` call, and every `agy models` discovery call, runs agy inside a freshly created `mkdtemp(join(tmpdir(), 'dsh-agy-'))` directory, removed in a `finally` regardless of outcome. agy's own settings (`~/.gemini/antigravity-cli/settings.json`) list the harness checkout and the user's home directory as trusted workspaces; running inside an untrusted cwd instead means agy's headless print mode auto-denies every built-in tool action it attempts there, and a `SUCCESS` result with an empty response and a non-empty `denied_actions` list is surfaced as `LlmError('AGENT_TOOLS_DENIED')` rather than a silent empty answer. The untrusted-cwd swap is the enforcement backstop for a model that ignores the preamble; the preamble is what keeps a compliant model from trying in the first place and paying the extra turn's latency.

### Prompt-level tool calling, not `--json-schema`

Probing `--json-schema` against a real request showed the model ignoring the schema and running an additional turn that tried agy's own tools — an unreliable and unsafe path for the harness loop to depend on. Instead, `GenerateOptions.tools` (when non-empty) is rendered as a `[Available Tools]` JSON block followed by a fixed protocol instruction (`TOOL_CALL_PROTOCOL`) asking for a `{"tool_calls":[...]}` JSON object, optionally fenced. Because this is advisory prompt text rather than a provider contract, `stream()` buffers the whole response in tool mode (no live `text-delta` chunks) and parses the terminal `result.response` tolerantly after the fact (`src/tool-protocol.ts`): a ` ```json ` fence or the raw trimmed text, `JSON.parse`d, validated for a non-empty `tool_calls` array whose entries carry a non-empty string `name` and an object `arguments`. A match emits any surrounding prose as a leading text block, then one `tool-call` block per call (`CallId(crypto.randomUUID())`, `arguments` re-stringified as JSON) and `finish {kind: 'tool-calls'}`. Any parse failure — invalid JSON, a missing/malformed `tool_calls` array, a malformed call — degrades to treating the whole response as ordinary text with `finish {kind: 'stop'}`, exactly as if no tools had been offered: a model that ignores the protocol never fails the request, it just answers in prose.

### Dynamic `agy models` discovery

`Config.models` defaults to empty. An empty catalog means `listModels` spawns `agy models` (inside the same untrusted-cwd pattern) and parses its `<id>\t<display name>` lines, skipping any line without a tab as banner/log noise. A successful discovery is cached for the adapter instance's lifetime (an in-flight promise is cached and reused, so concurrent callers dedupe); a failed discovery is NOT cached and rejects with `LlmError('DISCOVERY_FAILED')`, so the next call retries. A non-empty configured catalog is served exactly as configured and never triggers a discovery spawn. `resolveModel` prefers a configured entry's own capacities, falls back to a discovered entry's display name when the catalog is empty, and falls back to `Config.defaultContextWindow`/`defaultMaxTokens` in every other case — the same negative-capability shape `llm-ollama` uses for an unlisted pass-through id.

### Everything else follows existing adapter conventions

`Config` (schemastery, `src/index.ts`) declares every field required-with-a-default — `binaryPath`, `printTimeoutSeconds`, `models`, `defaultContextWindow`, `defaultMaxTokens` — and `resolveAdapterOptions` is the one explicit resolve step re-validating bounds a bare object literal could still violate (programmatic construction bypasses Schemastery), matching the repo's "Explicit > implicit" rule; there is deliberately no `config = {}` default on `apply()`, because `ctx.plugin()` always resolves the Config schema (including its defaults) before calling it. `GenerateOptions.stop` throws `UNSUPPORTED_OPTION` (agy exposes no stop-sequence flag); `temperature`/`maxTokens` are silently unused instead, because the loop always materializes `maxTokens` from `resolveModel`'s `defaultMaxTokens` onto every request — throwing there would fail ordinary agent-loop calls, not just explicit ones. Any image (or other non-text) content block anywhere in history throws `UNSUPPORTED_CONTENT` before any subprocess spawns; reasoning blocks are rendered as `[reasoning] <text>` rather than dropped, unlike `llm-ollama`'s Ollama route (which has no passback field for them) — this route has no such constraint, so keeping them costs only tokens, not a wire-format decision.

### Subprocess transport (`src/agy-process.ts`)

Kept as its own module (testable without a real `agy` binary) around one invariant: `spawnAgy()`'s returned event stream never rejects — every failure (spawn error, non-zero exit, signal death) arrives as a typed `AgyProcessEvent`, never a thrown/rejected transport error. This is why `adapter.ts`'s event-consuming loops carry no generic catch-and-rewrap: the two throw sites inside them are already well-formed `LlmError`s, and adding a defensive catch around code that cannot throw anything else would be untestable dead code, not extra safety. Listeners attach synchronously right after `spawn()` (a same-tick ENOENT is never missed), stdin write errors are swallowed by their own no-op handler (writing to a process that failed to spawn raises EPIPE, and the `error` handler above already reports the one real failure), and stderr is retained as a byte-bounded (4 KiB) tail for error messages.

## Alternatives considered

- **`--json-schema` for tool calling** — rejected on measured evidence: the model ignored the schema and ran an extra turn against agy's own tools instead of answering structurally. A prompt-level protocol the harness parses tolerantly, with a plain-text fallback on any failure, is strictly safer: worst case is a normal text answer, not a wasted turn or a misrouted tool attempt.
- **Trusting agy's own permission prompts / `permission_mode` instead of an untrusted cwd** — rejected: headless print mode has no interactive prompt to answer, and permission_mode is a display field on the `init` event, not a lever this adapter can set. The untrusted-cwd/auto-deny combination is the only currently-observed mechanism that reliably stops agy's own tools without an interactive session.
- **A shipped default catalog of known agy models** — rejected as a hardcoded tunable with no current-deployment justification: which models an agy installation can reach is account/subscription state this package cannot know, exactly the `llm-ollama` "empty `models` by default" precedent for deployment state a package cannot observe. `agy models` discovery answers the same need without a maintained, driftable static list.
- **Mounting this adapter in a shipped bundle** — rejected: `agy` is a separately installed, separately authenticated CLI, not something this harness can assume is present the way an HTTP provider with an API key is. The package stays opt-in, add-on-config-only, matching the task's explicit instruction.

## Consequences

- No live text streaming while tools are offered (buffer-then-parse is what makes prompt-level tool calling possible at all); a caller that needs live tokens during a tool-capable turn does not get them from this route.
- The prompt-level tool protocol is unenforceable: a model that emits well-formed `{"tool_calls":[...]}` JSON that happens not to be a genuine tool call would be misread as one, and there is no way to distinguish that from outside the model's own compliance.
- Every request pays roughly 14k input tokens of agy's own system-prompt overhead that this adapter cannot reduce, disable, or observe — agy assembles it before this adapter's stdin is even read.
- No cross-call KV-cache reuse of any kind: each `stream()` call is a brand-new agy process and conversation, so there is no session or prompt-prefix reuse for this adapter to report.
- The untrusted-cwd/headless-auto-deny fence is agy-version-dependent, not a hard sandbox guarantee this package owns; a future agy release that changes either behavior needs this package revalidated against the new binary, not just documentation updated.
- `agy models` discovery caches successes for the adapter instance's lifetime, so a model added to the account after the first successful discovery is invisible until the harness process restarts (a fresh adapter instance).

## Testing

- `packages/llm/llm-antigravity/tests/prompt.spec.ts` — the fixed preamble and tool-protocol text stay prefix/substring-stable, system text inclusion, transcript rendering by message-source `kind` (including the merge-extensible default fallback), tool-call/tool-result block rendering, and `UNSUPPORTED_CONTENT` for an image anywhere in history including nested in a tool result.
- `packages/llm/llm-antigravity/tests/tool-protocol.spec.ts` — fenced/unfenced/prose-surrounded parses, every malformed-shape rejection (non-array, empty array, missing/empty name, missing/non-object/array-typed arguments, non-object top-level JSON), and the fence-without-trailing-newline edge.
- `packages/llm/llm-antigravity/tests/agy-process.spec.ts` — `boundedAppend`'s exact/oversized/multibyte-split byte bounds directly, then `spawnAgy()` end to end against a generated (not git-exec-bit-dependent) fake `agy` executable: ordered line/exit events, a same-tick ENOENT `spawn-error` event before any exit, `kill()` idempotency and its effect on a hung process, a bounded stderr tail from a failing process, an early consumer `break` closing cleanly, and a large stdin write racing a child that exits without reading it (EPIPE).
- `packages/llm/llm-antigravity/tests/adapter.spec.ts` — every scenario the README documents end to end against the fake binary: live vs. buffered text, all four tool-call parse outcomes (fenced, fenced-with-prose, unfenced-multi-call, invalid/non-JSON fallback), `result.status: 'ERROR'` (with and without an error message), `denied_actions`, `EMPTY_RESPONSE` (with and without usage), non-zero exit and death-by-signal (both distinct from a caller abort), a missing `result` event, a malformed NDJSON line, `stop`/pre-aborted-signal rejection, ENOENT vs. a non-ENOENT (EACCES) spawn failure, the untrusted temp cwd's creation/distinctness/removal, mid-stream abort and early-consumer-return cleanup (a marker file the child writes proves its cwd is gone afterward), `agy models` discovery caching/failure-retry/configured-catalog-bypass, and `resolveModel` capacity resolution across every catalog shape. Per-file 100% coverage of `src`.
- `packages/llm/llm-antigravity/tests/index.spec.ts` — `Config` schema defaults and rejections, `resolveAdapterOptions` bound validation (including catalog dedup/detachment), and HMR-safe provider registration/disposal.
- `packages/llm/llm-antigravity/tests/loader-composition.spec.ts` — the real-composition guard `packages/CLAUDE.md` requires for a product-visible plugin: `LlmRuntime` and `llm-antigravity` booted from a test-only `cordis.yml` through the actual Loader, with a request reaching the fake `agy` binary and coming back assembled.
- A real-API smoke check (not committed as a test; costs the operator's own agy subscription quota) confirmed the built adapter against `gemini-3.8-flash-low`: a plain-text request and a tool-offering request both round-tripped correctly, the latter producing a `tool-calls` finish.
